# EPANN_replay: replay in evolved plastic neural networks

**Research question:** Which properties of replay are sufficient to ameliorate catastrophic forgetting in task-incremental learning, and what is the minimal architecture that supports it?

Instead of training a network with backpropagation, this project *evolves* small recurrent networks that learn on their own through neuromodulated synaptic plasticity, and tests whether an offline "replay" phase generated by the same network protects an earlier task while a second one is learned.

> **Status:** active research code. Experiments and results are not yet published, and configs and result data live outside this repository.

## The setup

- **Task:** a T-maze with a context cue (the current rule) and a sensory cue (reward location under that rule), after Soltoggio et al. (2008). Task A maps the cue directly, task B mirrors it.
- **Paradigm per evaluation:** train A, replay, train B, replay, test A. Replay is driven by a null input vector and the network's own noisy dynamics. Paradigms are defined by a string such as `trainA, 100, replay, 10, trainB, 50, replay, 30`.
- **Agent:** a continuous-time RNN (CTRNN). Every synapse has its own plasticity rule (Hebbian A/B/C/D coefficients) gated by modulatory connections. Evolution optimizes the *plasticity*, not the weights; starting weights are random in each evaluation.
- **Optimization:** PGPE with the ClipUp optimizer (EvoTorch), with CoSyNE as an alternative. Fitness combines task reward, a replay term and an L1 complexity penalty.
- **Study design:** no replay, unrewarded replay and rewarded replay, plus lesion controls (replay disabled or replaced by sham replay at test), each in both task orders.
- **Readouts:** per-task reward, forward and backward transfer (Lopez-Paz & Ranzato, 2017), the L1 penalty, and the decisions of the evolved agents per generation. Further continual-learning metrics are planned.

## Engineering notes

- The whole population is simulated as **batched tensors on the GPU** (PyTorch), including the plastic weight updates (`sim_core/ctrnn.py`).
- **Reproducibility by design:** deterministic algorithms, fixed `CUBLAS_WORKSPACE_CONFIG`, and separate RNG streams for noise and reward placement.
- **Loud failures:** configs and CLI arguments are validated and fail with explicit errors instead of silently falling back to defaults.
- **Early termination** of runs that collapse onto a degenerate always-left/always-right policy, to save compute.
- **Batch runner** that works through a folder of configs with parallel chains, per-machine runtime logs and automatic cross-config summary plots. Results are written as HDF5 and CSV.

## Layout

```
sim_core/   CTRNN + plasticity, maze task, fitness, genome codec, paradigm parser
runners/    run_evolution.py (one run), run_batch.py (sweeps over a folder of configs)
analysis/   plotting, recording of evolved networks, result I/O, strategy summaries
helpers/    config generation, genome plots, runtime comparisons
```

## Usage

Requires Python 3 and a CUDA-enabled PyTorch build (see `requirements.txt`; set the device to `cpu` to run without a GPU).

```bash
pip install -r requirements.txt

# one run: <config_name> <experiment_name> <device> <chain_label> <early_termination_enabled>
python runners/run_evolution.py my_config my_experiment cuda:0 manual True

# a sweep over every config in configs/<folder>/
python -m runners.run_batch my_folder my_experiment cuda:0 1 my_machine True
```

Each run is described by a JSON config in `configs/`.
